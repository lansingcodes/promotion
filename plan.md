# Lansing Codes Promo Pipeline — Implementation Plan

## Context

Lansing Codes is a nonprofit developer community in Lansing, Michigan that hosts roughly one event a month, listed on Meetup. Promoting each event currently means hand-writing the Meetup listing, making a speaker card image, writing social posts, and sending a monthly email. This project automates that work from a single source of truth.

Phase one (this plan): Lansing Codes' own events only. Phase two (later): Other local groups' events, from Meetup and other platforms, rolled into the monthly digest.

The design should not block phase two, but must not build for it yet.

## Goals

- Organizer input shrinks to: paste what the speaker sent, confirm date and venue, approve output.
- One event record produces every promotional artifact.
- Stack stays free or near-free: Canva Pro (nonprofit, already active), Buffer (free tier or 50% nonprofit discount), plain files in git.

## Non-goals (phase one)

- Automated posting to Meetup, Buffer, or email providers via API. Manual paste/upload is acceptable. See Open Questions.
- Other groups' events.
- Any web UI. CLI and Claude Code commands only.

## Event schema

One YAML file per event, named `YYYY-MM-DD-speaker-slug.yml`.

```yaml
# --- Organizer input ---
date: 2026-10-14
start_time: "18:00"
end_time: "20:00"
title: "Raw title from speaker"
speaker:
  name: "Jane Doe"
  title: "Staff Engineer"
  company: "Example Co"
  photo_url: "https://..."
  bio_raw: |
    Whatever the speaker sent, if anything.
description_raw: |
  Whatever the speaker sent.
venue:
  name: "Venue Name"
  address: "123 Main St, Lansing, MI"
registration_link: "https://www.meetup.com/..."   # not Meetup-specific by design

# --- Generated by /draft-event (organizer reviews) ---
generated:
  title: ""
  hook: ""                  # one line, used on image and in email
  description_long: ""      # Meetup listing body
  speaker_bio_short: ""
  captions:
    announce: ""            # ~3 weeks out
    week_before: ""         # topic-angled, not logistics
    day_before: ""
    day_of: ""
  email_blurb: ""
status: draft               # draft | approved | published
```

`registration_link` is deliberately generic so phase two can take Eventbrite or plain website links.

## Tasks

### 1. Scaffold repo and CLAUDE.md

- Create the structure above.
- `CLAUDE.md` contains: Lansing Codes description and boilerplate, voice and tone rules, words and phrasing to avoid, hashtag conventions, caption length limits per platform, the event schema, and the posting cadence.
- Add a sample event file with realistic thin input (title + one paragraph, no bio) for testing.

Done when: a new contributor can read `CLAUDE.md` and understand the whole pipeline.

### 2. `/draft-event` slash command

- Input: path to an event YAML file.
- Reads organizer fields, fills every field under `generated`, writes back to the same file.
- Must handle thin input gracefully — missing bio, one-sentence description. Never invent speaker credentials or facts not in the input; flag gaps instead.
- Must not overwrite organizer input fields.
- Rerunning on an approved event requires confirmation.

Done when: running it on the sample event produces a clean, reviewable diff with usable copy in the house voice.

### 3. Canva bulk-create export

- Reads all events with `status: approved` (optionally filtered by date range).
- Writes `out/canva-bulk.csv`.
- Column headers must exactly match the named data fields in the Canva template. Keep the mapping in one config block so it is easy to change when the template changes.
- Suggested columns: `title`, `hook`, `speaker_name`, `speaker_title_company`, `speaker_photo`, `date_display`, `time_display`, `venue_name`.
- Format dates and times for display (e.g. "Tue, Oct 14 · 6:00 PM").

Done when: the CSV imports into Canva bulk create and fills the square, and story templates with no manual fixes.

### 4. Posting schedule

- For each approved event, compute four post dates:
  - Announce: 21 days before
  - Reminder: 7 days before
  - Day before: 1 day before
  - Day of: event date (organizer may swap for a post-event photo)
- If the event was confirmed late and the announce date is already past, schedule announce for the next day and note it.
- Write `out/buffer-schedule.csv` with date, time, caption, image filename, and link.
- Match Buffer's bulk upload CSV format (verify current format before building).

Done when: the CSV uploads to Buffer and creates correctly dated drafts.

### 5. Monthly email digest

- Input: a month (`2026-10`).
- Gathers approved events in that month, sorted by date.
- Renders `out/digest-2026-10.html` and `.txt` from the templates.
- Each event: title, hook, date, time, venue, email blurb, registration link.
- Intended send date: first of the month.

Done when: the HTML pastes cleanly into the mailing list tool and renders on mobile.

## Workflow once built

1. Speaker confirms → organizer creates event YAML with raw input.
2. Run `/draft-event` → review and edit the diff → set `status: approved`.
3. Run Canva export → bulk create images → download.
4. Run schedule script → upload to Buffer with images.
5. Paste `description_long` into Meetup.
6. On the 1st of the month, run the digest and send.

## Ownership (decide before launch)

- Who creates event files?
- Who approves generated copy?
- Who uploads to Buffer and sends the digest?

## Open questions for Claude Code to investigate

Do not let these block phase one.

- Meetup API: can listings be created or updated programmatically, and on what plan? If gated or unavailable, manual paste stays.
- Buffer API: does the free or nonprofit plan allow API scheduling, or is CSV bulk upload the ceiling?
- Mailing list provider: which tool does Lansing Codes use, and does it have an API worth integrating in a later phase?
- Canva API: is autofill via API available on the nonprofit plan, which would remove the manual bulk-create step?

## Suggested build order

Before writing any code, run one real upcoming event through the process by hand and save exactly what was produced at each step. Use that as the fixture and acceptance test for tasks 2–5.

Then: Task 1 → 2 → 3 → 4 → 5.

## Decisions log

- **2026-09-22 — Scripts are Node.js** (Node 22+, ES modules). One runtime dependency: [`yaml`](https://eemeli.org/yaml/), chosen because its Document API keeps comments and key order when `/draft-event` writes back to an event file. Tests use the built-in `node:test` runner.
- **2026-09-22 — Schema additions** (all optional, organizer-owned unless noted):
  - `venue.notes`: venue-specific lines for the listing (food, parking, drinks for purchase).
  - `generated.gaps` (written by `/draft-event`): missing facts the copy had to work around, such as "no speaker bio" or "no speaker photo". The organizer clears it once they've dealt with each one.
- **2026-09-22 — Fixtures live outside `events/`** (`fixtures/`), so the export and schedule scripts never pick up test data. Every script takes `--events <dir>` so tests can point it at `fixtures/events/`.
- **2026-09-22 — Mailing list provider is Mailchimp.** The lansing.codes newsletter form posts to `codes.us19.list-manage.com` (see `lansingcodes/www` `components/newsletter.vue`).
- **2026-09-22: Task 3 uses Canva autofill through the connector**, via the `/make-cards` slash command. Autofill proved to work on this account, so there's no CSV round-trip and photos go in automatically from `speaker.photo_url`. `npm run canva:csv` keeps the plan's CSV bulk-create export as a fallback. It leaves out `speaker_photo`, because Canva reads image URLs in a CSV as text. The Meetup-sized **banner** (1640×924) was added alongside the square and story.
- **2026-09-23: Task 4 uses the Buffer connector in Claude Code, not the CSV and not a raw API key.** The organizer connected Buffer, and the connector covers `create_post`, `list_channels`, `get_post` and the rest, with sign-in handled by the connector. `scripts/schedule.js` plans the posts (noon America/Detroit, the late-announce rule) and records the Buffer post IDs under `buffer_posts:` in the event file so reruns are idempotent. `/schedule-posts` creates them. Verified 2026-09-23: `saveToDraft: true` with `mode: customScheduled` keeps the `dueAt`, and the four Oct 20 drafts landed on X with their correct dates.
- **2026-09-23: Card images are hosted in this repo.** The repo is public at github.com/lansingcodes/promotion. `/make-cards` saves PNGs to `cards/` (committed), and Buffer fetches them from `raw.githubusercontent.com/lansingcodes/promotion/main/cards/`. Buffer has no upload endpoint and fetches media at publish time, so the link has to be permanent. Canva's export links expire after about a day.
- **Phase two pointer:** lansing.codes already aggregates other local groups' events through [`lansingcodes/api`](https://github.com/lansingcodes/api) (Firestore). [`lansingcodes/newsletter-events`](https://github.com/lansingcodes/newsletter-events) already turns that feed into newsletter-ready lists. Phase-two "Around town" ingestion should start from those projects rather than scraping Meetup.

## Open questions: findings (researched 2026-09-22)

Items marked **unverified** need a real test before the task that depends on them.

### Buffer (affects task 4)
- **Bulk upload CSV columns** are case-sensitive: `Text`, `Image URL`, `Tags`, `Posting Time`. `Posting Time` is `YYYY-MM-DD HH:mm`, 24-hour and zero-padded. Leave it blank to use the next queue slot. The timezone is probably the channel's timezone setting (**unverified**, so test with one row). Download a fresh template per channel from Buffer (Publish → channel → gear → General → Bulk Upload) and diff it against ours before building.
- **One channel per upload.** Posting to Facebook, X and LinkedIn means three uploads of the same CSV, or one CSV per channel.
- **Images must be public URLs.** Filenames don't work, which changes the plan's "image filename" column. The Canva PNGs need to be hosted somewhere public first, e.g. committed to a public repo or GitHub Pages. Another option: leave `Image URL` blank and attach images in Buffer by hand.
- **The Free plan works**, but it allows 10 posts per channel per upload and is capped by open queue slots. Four posts per event fits easily. At the last step you choose "Save as Drafts" or "Add to Queue".
- **API:** Buffer's new GraphQL API (beta) is open to new users on **every plan, including Free** (1 key, 3,000 requests per 30 days). It uses a personal API key; no OAuth app is needed. That makes it a realistic phase-1.5 upgrade from CSV. Sources: support.buffer.com/article/859, developers.buffer.com.
- **Nonprofit discount:** 50% off paid plans. Apply at buffer.com/nonprofit-request.

### Canva (affects task 3)
- **Bulk create can't pull images from URLs in a CSV.** Image URLs come through as plain text. Images have to be embedded one per cell in an **.xlsx** or Canva Sheet (**unverified**; the help page blocked scraping). So either:
  1. export a CSV for the text fields and drop speaker photos in by hand (one per event, about a minute), or
  2. generate an `.xlsx` with embedded photos, which adds a dependency, or
  3. keep the photo as a fixed frame the organizer fills.

  Start with option 1 and see whether it hurts.
- **Connect API Autofill requires Canva Enterprise** according to Canva's docs, for both the developer and every user.
- **Update 2026-09-22, tested:** autofill *does* work on this account through the Canva connector in Claude Code. `autofill-design` filled the banner template from a text payload and produced a correct card. So Task 3 can generate cards directly from Claude, with no CSV and no bulk create, and the photo can go in via `upload-asset-from-url` from `speaker.photo_url`. Keep the CSV export as the fallback in case the connector route stops working. The templates and fields are in `fixtures/2026-10-20-git-diff-my-brain/canva-fields.md`.

### Meetup (affects the "paste into Meetup" step)
- The GraphQL API has `createEvent` and `editEvent` (draft or publish), using OAuth 2.
- Creating an OAuth client reportedly needs an **active Meetup Pro subscription**, with approval not guaranteed (**unverified**; the help page blocked scraping). If Lansing Codes isn't on Pro, manual paste stays.

### Mailchimp (affects task 5)
- The provider is Mailchimp (see the decisions log).
- **Free plan limits:** 250 contacts, 500 sends a month, **no scheduled sends** (Essentials and up), and **no code-your-own HTML templates** (Standard and up).
- Task 5's HTML needs to paste into a regular campaign's **code/text content block**, not be imported as a template. Check the current plan and contact count before building task 5.
- The API can set raw campaign HTML and send. Scheduling needs Essentials.
